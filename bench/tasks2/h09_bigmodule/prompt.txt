Our services build their configuration by overlaying profile dicts onto the module-level DEFAULTS in configlib.py — and something is corrupting state between loads: after applying one profile, the shared DEFAULTS themselves contain the profile's values, so every later load starts from polluted defaults (e.g. load a profile with logging.level=debug once and from then on plain apply_profile({...}) calls report debug too). Combining configuration layers is never supposed to modify any of its inputs, top level or nested. configlib.py is large; track down the real cause, fix it there, and change nothing else. python3 driver.py reproduces the failure and must print DRIVER OK when the bug is gone.
