The mini web app in app.py mis-routes requests. Two observable bugs: dispatch("/users/7/extra") returns the user page with status 200 even though no route has that shape — a path with extra trailing segments must not match a shorter route and should 404; and dispatch("/orders/-2") returns a 500 "internal error" instead of a 404 — a route parameter typed <int:...> is only ever a plain non-negative decimal number, so "-2" (or "1.5", or " 3 ") should simply not match the route at all. Working paths like /users/7, /orders/12 and /health must keep behaving exactly as they do now. Fix the underlying causes rather than patching individual handlers.
